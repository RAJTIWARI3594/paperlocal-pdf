# Validation of the delivered build

These are observed results, not a certification or a claim that every PDF is supported.

## Automated core/output suite

`node --test tests/core.test.mjs`: **40 tests passed** on Node 24.20.0. Checks include range order/rejection, rotation normalization, input byte/count/type limits, malformed PDF handling, actual page-copy ordering/dimensions, additive rotation, selection omission and invalid export states. Fixtures are invented PDFs generated by the tests. Raw output: [core-test-results.txt](core-test-results.txt).

## Real-browser workflows

`uv run tests/browser_check.py`: **24 checks passed** on Linux Chromium 155.0.8059.79 with Playwright 1.55.0. The suite downloads actual PDF outputs and independently parses them with pypdf 6.1.1, checking text order, page count, page dimensions, rotations and embedded images. It uses synthetic PNG/JPEG images.

Covered workflows: actual previews and two-PDF merge; deselection/reorder/rotation; explicit extraction order; invalid ranges; empty selection; output while the browser is offline after load; one-file-mode limits; clearing; protected/malformed/empty/wrong-type input; atomic invalid batches; A4 and original-size photo output; photo reordering/rotation; safe download names; 390px mobile fit; standalone Organize; escaped filenames; keyboard focus participation. Only same-origin static GET requests and **zero document-upload or third-party requests** were observed during this suite; no uncaught JavaScript errors occurred. Exact checks: [browser-validation.json](browser-validation.json).

The app's desktop and mobile screenshots are from these actual running workflows. They were visually inspected, including page controls and the download UI. Output PDFs were parsed independently; organized PDF text order was also inspected through a PDF reader. The photo fixtures are plain synthetic color images, not personal photographs.

## Not verified

No physical phones, Safari, Firefox, screen-reader audit, exhaustive WCAG audit, load/stress test to stated limits, malicious-PDF safety audit or professional security review. A viewport check is not a physical-device test. JPG/PNG decoding uses the browser's orientation handling, but exhaustive EXIF variants were not tested. Complex fonts/CMaps/JPEG2000 previews are not guaranteed. No compression, Office conversion or production deployment is claimed.

## Packaging check

The source ZIP contains bundled runtime dependencies, license notices, docs, tests and real screenshots, but no runtime documents/databases, credentials, node_modules, caches or Git history. Its contents were integrity-tested and compared byte-for-byte with the source manifest. A clean extraction reran the core and browser suites successfully; the packaging receipt is retained outside the source package.
